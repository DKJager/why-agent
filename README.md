# Why-Agent

**Open Agent Hackathon 2026 · Track 02 "The Agent That Can Explain Why"**

> **FICTIONAL DATA.** "Northwind-Lite", every customer, order, carrier (NordExpress, RheinFracht, ...) and ticket in this repository is synthetic, generated by `data/generate_sample_data.py`. No real company, person or carrier is represented.

Why-Agent investigates a business question such as *"Why did EU revenue drop in week 41?"* across three data sources (orders, support tickets, shipments), joins the findings, and returns an evidence-backed answer together with a visible reasoning trace. Four agents (Planner, Investigator, Critic, Explainer) cooperate; a Critic re-verifies every claim against the data before it can reach the answer.

## Quick start

```
pip install -r requirements.txt
SAMPLE_MODE=true python run.py "Why did EU revenue drop in week 41?"
```

Docker (offline by default):

```
docker build -t why-agent .
docker run --rm -p 8000:8000 why-agent
curl -s localhost:8000/run -H 'content-type: application/json' \
  -d '{"input":{"query":"Why did EU revenue drop in week 41?"}}'
```

Secrets are passed at runtime (`--env-file .env`), never at build time. For live mode use `-e SAMPLE_MODE=false` plus credentials.

## Usage

### CLI

```
python run.py "QUESTION" [--run-id ID] [--json] [--out PATH] [--sample]
python run.py --serve [--port N]
```

- `--json` prints only the result JSON on stdout (log lines go to stderr). Without it, stdout carries the log lines (the last is `Completed in ...`) and the human-readable answer is printed to stderr.
- `--out PATH` also writes the result JSON to a file.
- `--sample` is shorthand for `SAMPLE_MODE=true`.
- Exit codes: `0` success or partial, `1` structured error result (JSON still printed), `2` usage error.

### HTTP

- `POST /run` (body up to 64 KB): `{"run_id": "demo-001", "input": {"query": "..."}, "options": {"sample_mode": true, "fallback_to_sample": false, "max_refinements": 2, "memory": {"enabled": true}}}`
- `GET /healthz`: `{"status":"ok","sample_mode":bool}` (process-up only).
- Status mapping: success/partial 200; `InvalidRequest` 400; `QuestionNotSupported` and `NoData` 422; `ProviderUnauthorized`/`SourceUnauthorized` 502; `ProviderUnavailable`/`SourceUnavailable`/`EngineNotConfigured` 503; `UpstreamTimeout`/`RunTimeout` 504; `ConfigError`/`InternalError`/`IterationLimit` 500.

### Trace file

Every run writes `logs/trace-<run_id>.jsonl`, one JSON object per line with `timestamp, run_id, agent_name, action, input_summary, output_summary, target_agent, confidence, retry_count, status` plus `step`, `kind`, `duration_ms` and `details`. Read it top to bottom: `delegate_task` lines show the hand-offs, `source_query` the data access, `reject_claim`/`accept_claim` the Critic's decisions, `engine_call` the memory recall and store.

### Errors

Errors are structured JSON: `{"run_id", "status":"error", "error": {"type", "message", "recoverable", "details"}, "trace_id", "log_file", "execution_time_seconds"}`. Messages are redacted and never contain stack traces or secrets.

## How it works

1. **Planner** parses the question, recalls H-MEM records for the question's entities and splits it into per-source sub-questions (shipments are prioritised when memory mentions a carrier).
2. **Investigator** builds `QuerySpec` objects (never free-form SQL), computes deltas, decomposes the change by segment, joins orders, shipments and tickets, and proposes claims whose numbers are references into evidence values.
3. **Critic** rejects any claim that has no citation, cites unknown evidence, has numbers that do not match the evidence, has ungrounded numbers in its text, fails re-computation (it re-runs the evidence query through the data source), cites missing rows, is a driver backed by a single source, or is a memory claim without a stored record. Rejections trigger at most `MAX_REFINEMENTS` refinement loops. Whatever remains rejected is reported in `output.unverified`, never in the answer text.
4. **Explainer** writes the answer from accepted claims only. The narrative is verified by the Critic; on failure the deterministic renderer in `agent/rules.py` is used.

**The model never produces numbers.** All numbers come from code that queries the sources. A model only helps with language, and a narrative is accepted only if every number in it maps to an accepted claim.

**H-MEM.** Confirmed driver and delta findings (confidence >= 0.7) are stored per entity (`carrier:`, `region:`, `week:`, ...) and recalled in later sessions. Recalled memory is a hypothesis, not evidence: it can never support a driver claim.

## Dependencies

Python 3.12 and `requests` only.

## Data

Source: generated by `data/generate_sample_data.py` (seed `20261022`, stdlib `random`), CC0. Subset: ISO weeks 35-42 of 2026 (2026-08-24 to 2026-10-18). Regenerate byte-identically with:

```
python data/generate_sample_data.py
```

## Samples

`samples/questions.json` holds three questions: 01 is the main case (a carrier-delay explanation with demand ruled out), 02 runs after 01 against the same memory file and shows H-MEM recall, 03 is a false-premise negative control. Outputs in `samples/outputs/` are produced only by the script below and are never hand-written:

```
python scripts/run_samples.py
```
